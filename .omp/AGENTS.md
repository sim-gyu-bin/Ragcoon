# RAGcoon 작업 규칙

RAGcoon은 구현한 코드를 사용자가 직접 실행하고 질문하며 배우는 프로젝트다. 데이터·비용·운영 경계는 [핵심 규칙](RULES.md)을 따른다.

- **질문과 수정 요청을 구분한다.** “어떻게 동작해?”, “왜 이렇게 했어?”에는 현재 코드의 진입점과 호출 흐름으로 답한다. 검토·설명만 요청받았다면 코드를 바꾸지 않는다. 아직 구현하지 않은 기능은 계획이라고 밝힌다.
- **한 단계에 관찰 가능한 기능 하나를 완성한다.** 요청한 단계의 구현과 검증은 함께 마치되 다음 로드맵 단계를 미리 만들지 않는다. 새 의존성은 그 기능에 필요한 이유가 있을 때만 추가한다.
- **직접 작성하는 코드 주석은 한국어로 쓴다.** 단순 대입이나 함수 호출처럼 코드만 읽어도 알 수 있는 동작은 설명하지 않는다. 대신 부분 색인된 문서를 검색에서 제외하는 이유처럼, 코드만으로 알기 어려운 선택의 이유나 조건을 바꿨을 때 생길 문제를 설명한다. 동작을 변경하면 관련 주석도 함께 갱신한다.
- **변경한 경로를 검증한다.** API는 요청과 응답, UI는 실제 화면, 검색은 질문에 대해 반환된 원문으로 확인한다. RAG에서는 검색된 근거와 생성한 답변을 따로 살펴 답이 틀린 지점을 구분한다.
- **위키 갱신은 단계 완료 기준에 포함한다.** 재사용할 설계 이유나 검증 한계가 새로 생기거나 바뀌면 [학습 위키](../docs/wiki/README.md)의 해당 주제를 갱신하고 완료 보고에 링크한다. 새 주제는 위키 목차에도 연결한다. README는 프로젝트 소개·실행 방법이 바뀔 때만 수정하고, 단계별 진행 상태는 작업 플랜에 기록한다.
- **완료 보고는 다시 따라 할 수 있게 쓴다.** 실행 위치와 명령, 기대할 관찰 결과, 처음 읽을 `파일 경로 + 함수·컴포넌트`, 핵심 선택 이유를 짧게 남긴다. 실제 실행 결과와 미확인 조건을 구분한다.
- 버전·호환성·과금 조건이 구현을 좌우하면 [공식 근거 확인](skills/source-verification/SKILL.md)을 사용한다. 이전 결정 조회나 재사용할 지식 정리는 [학습 Wiki](skills/llm-wiki/SKILL.md)를 따른다. 단순 질문마다 외부 조사나 문서 작성을 반복하지 않는다.
