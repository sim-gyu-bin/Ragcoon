# RAGcoon 단계별 작업 플랜

기준: [제품 요구사항](prd.md) · [프로젝트 개요](../README.md). 아래 체크박스는 실행 순서이며 완료 보고가 아니다.

## 진행 방식

- **한 번에 체크박스 하나.** 사용자가 단계 번호를 지정하면 AI가 그 단계의 설계·구현·관련 검증까지 맡는다. 다음 번호로 자동 진행하지 않는다. 실패하면 해당 단계 안에서 원인을 좁히고, 검증되지 않은 항목은 체크하지 않는다.
- **사용자는 결과를 확인하고 질문한다.** 단계 끝에 AI가 직접 관찰한 결과, 사용자가 선택적으로 재현할 명령이나 화면 경로, 먼저 읽을 파일·함수와 선택 이유를 남긴다. 설명 요청만으로 구현을 바꾸지 않는다.
- **계정 작업도 AI가 조사한다.** 로그인·MFA·비밀 입력처럼 본인만 할 수 있는 동작과 비용·권한·외부 공개·운영 변경·삭제 승인은 사용자가 맡는다. 키나 비밀번호를 채팅으로 요청하지 않는다. 단계 착수는 커밋·푸시·배포 승인을 뜻하지 않는다.

## 로컬 개발 — 한 턴에 하나의 사용자 시나리오

각 단계의 화면 검증은 호스트 개발 서버가 아니라 Docker Compose의 Caddy 주소에서 한다. 단위 테스트는 외부 API·운영 데이터 없이 실행하고, 유료 호출은 샘플과 범위를 승인받은 실험에서만 한다.

- [x] **L01 · 브라우저에서 백엔드 연결 확인 (F1).** `apps/api`에 uv·FastAPI의 `GET /api/health`, `apps/web`에 pnpm·React·Vite·TypeScript 연결 화면을 만든다. Compose에서 Caddy가 React 빌드를 제공하고 `/api/`는 경로를 유지해 FastAPI로 전달한다. 호스트에는 Caddy만 `127.0.0.1`에 공개한다. **완료:** 같은 주소에서 `/`는 화면, `/api/health`는 FastAPI의 JSON을 반환하고, FastAPI만 중단하면 화면은 열리되 연결 실패가 표시된다. DB·모델은 아직 쓰지 않는다.
- [x] **L02 · Markdown을 올리고 원문 위치 확인.** 파일 제한·보관 정책을 정하고 등록·목록 화면, SQLite 문서 상태, 청크 분할을 연결한다. **완료:** 같은 이름의 두 파일이 별도 문서로 보이고 청크 ID로 한국어 원문 구간을 확인할 수 있다. 등록만 된 문서는 검색 준비 상태가 아니다.
- [x] **L03 · 한 질문으로 세 검색 모드 비교 (R1).** 문서를 명시적으로 색인하고, 두 색인이 준비된 문서만 검색한다. 기본 하이브리드(RRF), 선택형 희소(SQLite FTS5/BM25)·밀집(ChromaDB) 검색을 연결했다. **검증 범위:** Caddy 화면의 모드 전환과 빈 결과, 외부망 차단 환경에서 합성 임베딩을 이용한 실제 DB 색인·상위 청크·출처 조회. 실제 OpenAI 임베딩 호출과 모델의 한국어 검색 품질 측정은 포함하지 않았다.
- [x] **L04 · 근거를 확인할 수 있는 채팅 (R2·C1).** `gpt-4.1-mini`에 현재 질문과 선택한 방식의 검색 근거만 전달하고 인용·스트리밍·세션별 기록을 연결했다. **검증 범위:** 격리된 Compose에서 로컬 합성 모델 응답을 Caddy·브라우저까지 전달해 완료 전 첫 조각, 인용 원문 열기, 새로고침 복원, 세션 분리, 근거 없음과 생성 도중 실패 상태를 확인했다. 실제 OpenAI 답변 품질과 과금은 측정하지 않았다.
- [x] **L05 · PDF 등록부터 문서 삭제까지 (D1·D2).** 텍스트 PDF의 페이지·줄과 인용 원문 일치, 이미지 전용 PDF 거절, 삭제 확인 취소를 검증했다. L07에서는 승인된 격리 문서 2건을 색인한 뒤 1건만 삭제했다. 목록과 희소·밀집·하이브리드 검색 모두 나머지 ID만 반환했고, 이전 대화의 인용 원문은 보존됐다.
- [ ] **L06 · 기본 RAG와 Agent 비교 (A1·E1).** 한국어 질문 약 10개로 기본 RAG의 기준선을 먼저 잡은 뒤 LangGraph의 판정·허용 도구·상한 있는 재검색을 연결한다. **완료:** 표현을 바꾼 질문·정확한 용어·근거 없는 질문에서 모드별 상위 3개 정답 문단 포함률, 인용 정확성, 근거 부족 응답을 구분한다. 같은 질문으로 기본 RAG와 Agent를 비교하고 실제 실행 경로와 종료 조건을 확인한다. LangSmith는 전송 필드·비용 승인 후 합성 예제로 확인하고, 꺼도 질의응답이 동작해야 한다.
  - **로컬 검증 완료, 원격 추적 미검증.** 외부망 없이 한국어 합성 질문 10개(정확한 용어 4·바꾼 표현 4·근거 없음 2)를 세 모드·두 전략으로 실행했다. 60건 중 실행 오류는 없었다. 희소 시작 시 상위 3개 정답 문단 포함은 기본 4/8 → Agent 7/8, 완료 답변의 인용 정확성은 4/5 → 7/8이었다. 밀집·하이브리드 시작 시 두 지표 모두 양쪽 8/8이었다. 모든 조합에서 무근거 질문은 2/2 거절했다. 실제 OpenAI 품질 수치가 아니다.
  - Caddy 화면에서 `복사본`을 희소 검색해 기본 RAG의 `no_results`와 Agent의 하이브리드 재검색 후 `answered`, 인용한 `study.md` 1줄 원문을 확인했다. LangSmith SDK의 전송 필드는 로컬에서 확인했고, 승인 범위에 따라 실제 원격 기록은 보내지 않았다.
- [x] **L07 · 로컬 인수 검증.** 격리 데이터와 Caddy 화면에서 등록 → 검색 → 인용 답변 → 기록 복원, 컨테이너 재생성 후 데이터 보존을 확인했다. 아래 실제 모델 평가와 오프라인 인수 검사는 별도 실행이다.
  - **오프라인 인수 통과.** Pytest 57개와 하위 검사 67개, Vitest 2개, Biome·TypeScript·Vite 빌드 통과. 격리된 Caddy 주소에서 Markdown 등록·색인 → 하이브리드 검색 → 채팅 답변과 인용 원문 확인 → API·Caddy 컨테이너 교체 → 같은 세션·인용·검색 결과 복원까지 확인했다. 첫 기동 시 API 준비 전에 화면이 502를 받을 수 있어 Caddy가 `/api/health` 성공을 기다리도록 변경했다.
  - **실제 모델 평가 완료.** `text-embedding-3-small`·`gpt-4.1-mini`로 합성 질문 10개 × 검색 방식 3개 × 전략 2개를 한 번씩 실행했다. 실행 오류 0건. [검색·인용 지표와 누락 사례](wiki/evaluation.md#실제-모델-평가-결과)를 참고한다. LangSmith 원격 기록 및 OCI 배포는 실행하지 않았다.

## OCI — 구현량보다 승인·공개 범위가 달라지는 지점에서 나눈다

이 단계의 오사카 A1·2 OCPU·12GB·Ubuntu 24.04 ARM64는 **목표 사양**이다. 기존 VM의 존재, 무료 적용, 여유 용량을 가정하지 않는다.

- [ ] **O01 · 읽기 전용 실사와 배포안.** 허용된 컴퓨터 유즈 세션에서 AI가 OCI 리전·구획, 기존 VM 용도·사양·디스크, 접속·네트워크·한도·비용을 확인한다. DNS·GitHub 권한도 필요한 범위만 조회한다. **완료:** 관찰값과 미확인 항목을 구분하고 재사용 또는 신규 구성, 예상 비용, 접근 통제·호출 한도, 변경·백업·복구 범위를 제안한다. 사용자는 자료를 수집하지 않고 안을 확인한다. 비밀·접속 식별자는 저장소에 남기지 않는다. 이 단계에서는 자원을 변경하지 않는다.
- [ ] **O02 · 승인된 VM에서 비공개 기동.** 승인 범위에서 접속·Docker·ARM64 이미지·디스크를 확인하고 서버 측 비밀과 영구 볼륨으로 Compose를 올린다. 로컬 DB는 복사하지 않는다. **완료:** VM 내부에서 health와 합성 문서 검색이 동작하고 API·DB 포트는 외부에 열리지 않는다. 비용이나 기존 서비스 영향이 승인안과 다르면 멈춘다.
- [ ] **O03 · 접근 제어를 갖춘 HTTPS 배포.** 승인된 DNS·인바운드·Caddy 변경과 GitHub Actions 검사·빌드·승인 배포를 연결한다. **완료:** 검사 실패는 배포를 막고, 승인된 리비전에서 허용된 사용자만 HTTPS로 업로드·질의할 수 있다. 직접 API 요청의 미인증 거절, 호출 한도, 외부 전송 설정을 확인한다.
- [ ] **O04 · 백업 복구와 운영 인수.** 합의한 주기로 백업을 구성하고 격리된 위치에서 복원한다. **완료:** 운영 데이터를 건드리지 않고 복원본의 문서·검색·대화를 대조한다. 이미지 롤백과 DB 복구를 구분해 설명하고 상태·오류·비용 확인 위치를 인계한다.

**첫 요청 예시:** `L01만 진행해줘.` 이후에는 번호를 지정해 이어가거나, 다음 단계로 넘어가기 전에 방금 만든 코드에 대해 질문한다.
