# 한 문단이 답변의 출처가 되기까지

## 등록과 색인

**등록은 읽을 원문을 보관하는 일이고, 색인은 나중에 찾을 수 있게 만드는 일이다.** 등록만 했는데 검색 결과가 비어 있다면 먼저 문서 상태를 본다. [문서 API](../../apps/api/app/documents.py)는 Markdown을 문단 단위로 분할하고 원문과 줄 범위를 SQLite에 보관한다. 같은 파일명도 새로 등록하면 별도 문서 ID를 받는다. 키 없이 확인하려면 빈 줄로 나눈 합성 Markdown을 올려 ‘구간 펼쳐보기’에서 원문 줄과 청크를 대조한다. Markdown은 UTF-8, 최대 1 MiB다.

색인을 명시적으로 시작해야 외부 임베딩 API에 청크가 전달된다. SQLite FTS5는 단어가 일치하는 청크를, Chroma는 질문 벡터에 가까운 청크를 찾는다. **서로 다른 청크를 두 벌 만드는 것이 아니라 같은 청크 ID로 결과를 합친다.** 한쪽만 성공한 문서는 검색에 섞지 않는다. 재색인은 다시 비용이 들 수 있다. 저장소별 역할은 [DB 흐름](../db-flow.md), 실제 질의와 순위 결합은 [검색 구현](../../apps/api/app/search.py)과 [BM25·벡터·RRF 설명](../search-concepts.md)을 참고한다.

## 검색과 인용

**문단을 찾는 모델과 답변을 쓰는 모델은 다르다.** 검색 화면은 후보를 최대 3개 반환할 뿐 답변을 생성하지 않는다. 희소 검색은 SQLite에서 끝나고, 밀집·하이브리드 검색은 [임베딩 모델 `text-embedding-3-small`](../../apps/api/app/vectors.py)로 질문을 벡터화한다.

채팅에서 쓸 근거가 있으면 현재 질문과 후보 문단을 `gpt-4.1-mini`에 보내 답변을 작성한다. 스터디에서 반복 호출하는 비용을 고려해 `gpt-4.1` 대신 `gpt-4.1-mini`를 앱의 기본 답변 모델로 선택했다. 두 모델 호출은 같은 서버 `OPENAI_API_KEY`로 인증하지만, **임베딩 비용과 답변 생성 비용은 각 모델의 사용량에 따라 따로 발생한다.** 따라서 희소 검색으로 임베딩 호출을 생략해도 답변을 만들면 생성 비용이 든다. 일반 채팅은 후보가 없으면 생성하지 않고, 있으면 질문당 최대 한 번, 출력 상한 512토큰으로 호출한다.

[L07 실제 모델 평가](evaluation.md#실제-모델-평가-결과)에서도 `gpt-4.1-mini`의 역할은 앱에서와 같은 **답변 작성**이었다. 채점은 별도 [Python 코드](../../apps/api/evaluation/scoring.py)가 정답표와 인용 출처를 대조해 수행했다.

답변의 `[1]`은 전역 청크 ID가 아니라 **이번 답변의 출처 번호**다. 화면에서 번호를 눌러 문서명·줄·원문을 열고 실제 주장을 지지하는지 읽어 본다. 유효한 번호를 붙였다고 내용까지 맞는 것은 아니다. 대화는 SQLite에 복원용으로 저장하지만 전체 대화 내역을 모델에 보내지는 않는다. 읽는 순서: [검색 후보에서 답변을 만드는 코드](../../apps/api/app/chat_model.py) → [인용 판정과 대화 저장](../../apps/api/app/chat.py) → [원문을 펼치는 화면](../../apps/web/src/Chat.tsx).

## 페이지와 삭제

텍스트 PDF는 최대 5 MiB·100쪽이며, 바이너리 대신 페이지별 추출 텍스트를 보관한다. 출처의 ‘2페이지 · 1줄’은 **두 번째 PDF 페이지에서 추출한 텍스트의 첫 줄**이다. Markdown의 줄은 문서 전체 기준이다. 스캔본 OCR과 암호화 PDF는 지원하지 않는다. [PDF 추출](../../apps/api/app/pdf.py)과 [화면의 출처 표기](../../apps/web/src/sourceLocation.ts)를 함께 보면 두 기준을 구분할 수 있다.

문서 삭제는 ‘앞으로 검색할 지식’을 지우는 동작이다. 해당 ID의 원문·청크·단어 색인·벡터가 대상이며, **이전 대화에 저장한 인용 사본까지 지우지는 않는다.** 따라서 원본 삭제를 대화 내용의 완전 삭제로 해석하면 안 된다. [삭제 구현](../../apps/api/app/deletion.py)과 [삭제 테스트](../../apps/api/tests/test_deletion.py)를 참고한다. L07 격리 검증에서는 문서 두 건 중 한 건만 삭제하자 세 검색 방식 모두 남은 ID만 반환했고, 이전 대화에서는 삭제 전 인용을 다시 열 수 있었다. 이 실습을 재현할 때는 개인 문서 대신 삭제 범위를 승인한 합성 문서만 사용한다.
